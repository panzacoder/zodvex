# Zodvex 0.8.0-beta.3

This beta combines the tuple/literal mapping fix (#169, fixes #168) and the
codegen fingerprinting fix (#170). These are the only library changes since
published `0.8.0-beta.2`.

## Tuple and literal validators

- Tuples map to array validators matching their encoded representation, including
  fixed items and rest elements. Codec-containing tuples infer encoded wire types
  recursively, including nested tuples and trailing optional slots.
- Multi-value literals retain every distinct value. Null literals use `v.null()`;
  duplicate values produce the same validator shape as the inferred type.
- Generated source preserves all literal values, including null and bigint.

Deploying a tuple table field changes its validator from an object with `_0`,
`_1`, etc. to an array. Convex revalidates stored documents. Ordinary encoded tuple
arrays could not pass the previous validator, but manually stored objects matching
that old shape need migration. Convex validates the array's element types; exact
length and position are enforced only where zodvex runs Zod parsing. Existing
codegen omission of tuple `.rest()` remains outside this fix.

## Other changes bundled in this beta

Codegen now fingerprints nested schema checks rather than just top-level checks
(#170). This prevents a function codec from being replaced by a lookalike with
different nested limits. Codecs with refinements, lazy schemas, cycles, or
class-instance definition values cannot be matched structurally; they resolve by
identity or brand. A codec that previously matched a lookalike may now cause
codegen to fail with "no importable reference". Export the codec standalone (or
brand it) and reuse that instance in the function, then regenerate `_zodvex/`.

## Changes already released in earlier 0.8 betas

Compared with npm's stable `latest` (`0.7.11`), this beta also includes:

- Staged database, search, and vector indexes on `defineZodModel` (#152).
- Preserved table metadata for `zx.id()` across entrypoint bundles (#150).
- Correct modern-builder customization replacement types (#141), including
  optional argument/context fallback types corrected in beta.2 (#166).
- Repository skills, planning documentation, and benchmark/test maintenance
  (#161, #160, #148, #144); these are not new library runtime features.

## Release plan

Publish as `0.8.0-beta.3` on npm's `beta` dist-tag. Stable `latest` remains
`0.7.11`. Merging the version bump into main triggers automatic prerelease
validation and publication. Preparing this branch does not publish the package.
