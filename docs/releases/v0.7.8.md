# Zodvex 0.7.8

This stable release promotes the library code tested in 0.7.8-beta.3. It focuses on database type safety, query correctness, client error handling, and reliable code generation.

## Database helpers and composition

Use `PatchValue` and `WriteValue` from `zodvex/server` or `zodvex/mini/server` to name the input contracts of generic database helpers. The prefixed names from earlier betas remain aliases. Writer signatures now reject wire-format codec values, mismatched table IDs, and incomplete union variants more reliably.

Object patches remain partial. Modeled union patches can require a complete variant because their encoder uses the full union schema; patches do not validate the resulting merged document.

`initZodvex` supports an `underlyingDb` resolver for composing native wrappers such as convex-helpers triggers underneath the codec layer. `db.unwrap()` exposes that delegated database and explicitly bypasses Zodvex codecs, rules, and audit.

## Correctness fixes

- Invalid React query arguments throw their encoding error instead of remaining in a loading state.
- Decoded watch caches no longer expose stale values after failures.
- Database query expressions retain their native representation, and bounded scans close their iterators.
- Generated schema literals and property names are escaped safely.
- Zod-to-mini migration preserves receiver semantics and avoids repeated project analysis.
- Decode warnings omit raw-wire previews by default. `warnWirePreview: true` remains an explicit debugging option.

## Validation and compatibility

The beta.3 candidate passed 2,459 library/codemod/example tests plus type checks, builds, emitted declarations, lint, and generated-file checks. It also passed Hotpot's full local suite (1,799 tests plus 4 CLI tests, with 5 existing skips) and all GitLab CI jobs, including compatibility tests. Hotpot used Zod 4.4.3 and Convex 1.43.0; Zodvex's development baseline is pinned to Zod 4.5.4 without changing the published peer range.

Stricter write types can surface existing TypeScript errors. Use the named input types when forwarding values through generic wrappers. No descriptor-codegen migration is required.

This release does not include #80's descriptor architecture, `useQuery_experimental`, or #123's proposed experimental pagination restriction. Existing parsing, encoding, and client decode-error policies remain as documented in the boundary contract.
